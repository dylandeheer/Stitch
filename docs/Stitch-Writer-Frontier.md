# Conservative macro-read dependency experiment

This branch ports the conservative portion of [Lichii PR 805](https://github.com/zortos293/Lichii/pull/805), commit [`1d9b6ef31d`](https://github.com/zortos293/Lichii/commit/1d9b6ef31d7c271fcc955094cf37806478e2e3c6) by jpkto, with additional mapping, alias and shadow-comparison guards for Stitch's pinned renderer. It excludes QMD prediction and speculative readbacks. The original drain/flush path is the default. Hardware performance is unproven.

## Behavior

The baseline drains the entire split GPU queue, flushes buffer and query state on the back thread, and then reads the MME words. The experiment can read before unrelated queue entries finish. It first waits for the latest entry that may have written any guest memory and every entry that may have written the source range. It checks whether the buffer cache contains newer bytes and whether the query cache still holds a value or timestamp that overlaps even one of the bytes. Either condition runs the original full drain and flush. The normal read primitive still handles the syncpoint shim. The original words are delivered to the same load FIFO or data RAM indices.

- The front records ring positions after publication of each entry. Only the front accesses the writer table. Waiting uses the split's existing acquire load of the consumed position, which the back publishes after executing the entry.
- Default ring entries write anywhere. This includes the compute and copy engines, channel changes and deferred callbacks. All Maxwell draws (including guest mesh/task writes), possible deferred instance draws, reports and their fence callbacks, inline DMA uploads, barriers and unknown executable methods also write anywhere. Inert 3D register writes can be passed. The only memory-writing optimization in this port places constant-buffer words by their mapped device addresses. Upcoming support for additional methods requires a separate proof.
- Writes are classified in 256-byte granules against a fixed table of 1,024 latest positions (8 KiB). A colliding unrelated write may extend a wait. It cannot move the required position earlier. All mapped pieces are translated independently, so different GPU virtual aliases of the same device page meet in the same slot. Distinct device addresses can also share physical RAM. The candidate therefore checks the complete source against both forward and reverse device mappings; any aliased or unmapped backing returns to the unmodified full drain, buffer flush, and query flush, even when the lookup under the second device address found no held query. It preserves the baseline’s own DAddr-addressed flush policy and does not claim to resolve aliased query reports the baseline itself cannot find. Partially mapped, oversized, wrapping or potentially sparse-backed writes fall back to an unknown destination; unaligned MME reads use the baseline. GPU map operations already drain the split before subsequent commands (GPU::MapInOrder, ThreadManager::RunCommand.before_later_reads). Independent device Map/Unmap changes bump an existing generation. A change promotes every older noted writer to a dependency. The read obtains the device mapping mutex after waiting and checking both caches, requires the *same* generation, and copies the actual MME words while that mutex pins their identity. It does not hold the mutex while acquiring cache locks or waiting on the ring. A physical page at offset zero is distinguished from missing backing using the stored page-plus-one encoding. A read near the start of a physical page also refuses an ambiguously mapped predecessor that an unaligned eight-byte report write could cross.
- Physical query range checks hold the existing query-cache mutex and look back 15 bytes so a report beginning on the preceding page (value plus timestamp) is included. An implementation unable to inspect its cache conservatively reports that a query may be held.
- `Stop` resets ring positions, writer table and switch counters. Enabling the marker during a running session treats *all previously queued commands* as unknown writers before shortening any wait. A verification mismatch keeps the candidate disabled for this split instance, including an accuracy change and split restart.

## Hardware experiment

* With no variables set, the production macro read retains the original drain/flush. The writer table is inactive.
* `STITCH_WRITER_FRONTIER=1` permits the new path. Optional `STITCH_WRITER_FRONTIER_FILE=/path/to/diagnostics/writer-frontier` requires that file to exist. Adding/removing the file switches candidate/baseline on the next poll (up to 1,024 macro DMA calls). A filesystem error leaves the original behavior active. No file is created by the emulator.
* For the first gameplay run, also set `STITCH_WRITER_VERIFY=1`. Every read which would bypass the full drain is sampled before the drain and compared word-by-word with the original path after the drain. The actual MME always consumes the fully drained result during verification. A mismatch logs the macro, method and differing word index (no contents) and disables the candidate until the emulator exits. Query trace and command-page diagnostics retain their original behavior.
* Look for `Macro writer frontier`, `Macro writer reads` and `Macro writer verification failed`. The read summary reports cumulative attempted reads satisfying the static guards, how often waiting for a potential writer actually blocked, how often the full cache flush was safely bypassed, and how many such reads were compared. It prints every 65,536 attempts. Absence of mismatches without a nonzero comparison count is inconclusive.
* Verify several full passes through every scene needed (door, trees/leaves, water, lighting, camera movement, inside/outside). A mismatch is evidence of unsafe classification or concurrent changes. Investigate it before enabling unchecked operation. Verification adds a full drain to each candidate read, and cannot demonstrate speed. Only after clean comparisons should a separate run disable VERIFY and alternate the marker in the same section. Check median and p99 frame times, long hitches, true workload coverage and output correctness. The old 6.24% host CPU cycle share in Drain and up to ~250 ms/s of profile wall time do not establish an FPS benefit.

## Validation

The Linux build completed all seven release/test targets. All five CTest suites passed in 22.98 seconds. The main suite passed 892 cases (one skipped), including 86 assertions in eight focused dependency cases. Separate production-method cold-hint, query-slot and timestamp-recording replays passed, including negative controls. These tests do not prove game compatibility or speed.

Independent review found a real flaw in the first candidate: two distinct device addresses shared physical RAM. A queued constant-buffer write through one address was missed by a read through the other. The regression reproduced the old value instead of the queued value. The current patch checks reverse physical mappings, refuses ambiguous sources, pins the mapping during capture, and promotes earlier noted writes after mapping generations change. Physical page zero, unbacked and aliased trailing pages, remaps and a deliberately misclassified writer are covered. In verification mode the same failing read returns the fully drained result and disables the candidate.

The focused threaded tests live in `src/tests/video_core/maxwell_fast_method.cpp`, tagged `[gpu_split_dependencies]`. Hardware QA requires a nonzero compared-read count and no mismatches over repeated object, lighting and indoor/outdoor routes. Only then can an unchecked run measure frame-time benefit by alternating the runtime marker in the same scene.
