# Demand-time early buffer readbacks on Stitch

Base 72afed7463c79f307d65209fdabcb520538cf13c. Production freeze fd5aabdf87b5b39ff415156a22105429dd3714ed. This experiment adapts the bounded per-page learning, early copy, tick synchronization and bytewise reference verification from upstream Lichii #805 (783a9a34, 1072d4a1, 4c6864af, 4942eb8a, f01be636). It keeps the private copy outside guest RAM until a real reactive buffer demand. Upstream's QMD prediction, synthetic list-word placeholders, early writes to guest RAM and front-of-queue read bypass are excluded. Original attribution identified approximately 109 five-second reads at one page, and 217 reads after compute rewrites across that window. No source or test uses that address.

## Hardware controls and results to collect

- With no `STITCH_EARLY_READ_BASELINE_FILE` the experiment is off. To stage it, set that environment variable to the pathname of a marker before launching. A present file or filesystem error picks original synchronous reads. An absent marker, with that environment configured, enables learning/copies. The emulator checks every 16 frames. Switching arms clears training and cancels pending candidate copies. Allow several learned read-after-write cycles plus one complete 120-frame reporting window before measuring an arm.
- First run with `STITCH_EARLY_READ_VERIFY=1`. Ready and unready candidate copies are checked at eligible real reads. The queued original texture, buffer and query flush still runs. GPU-owned bytes the original download would really write, after CPU masks, are collected as the reference. A mismatch latches acceleration off until process exit. The actual game always receives the original bytes in this mode. Uncertain mapping identity, unproven original staging coherence, whole ranges protected by the CPU mask or incomplete time-line coverage do not certify a comparison.
- Compare deltas of the cumulative `Early buffer reads` fields. `ready_checks` counts actually compared snapshots ready when requested. `late_checks` counts snapshots that became ready during the original flush and were compared afterward. `late` and `unsubmitted` at demand are opportunities that a performance run must miss. `cpu_masked_bytes`, `empty_checks`, `remapped_checks`, `noncoherent_reference`, and `compared_bytes` explain coverage. `copies` and their bytes are speculative work, independent of hit/coverage counts. `stale` in this build counts retired slots including consumed or canceled copies; it does not count only conflicting writes.
- Only a separate non-VERIFY process with materially positive ready coverage and no mismatches can measure this candidate's gameplay effect. Compare stationary A/B/B/A or counterbalanced repeated route with the marker, keeping the selected tensor variant, graphics, audio, CPU/GPU clocks, and other query/read experiments fixed. Record actual nonzero `hits` and `hit_bytes`, readback-source/fence-wait counters, FPS and long-tail frame times. An almost entirely late or blocked result means this experiment did not address the observed stall. Do not infer any gain from a fake runtime, recorded copies, or upstream Windows measurements.

## Ownership, ordering and bounds

- 64 direct-mapped training slots require two observed reads following distinct conventional compute-storage writes; collisions relearn. Four unread rewrites retire eligibility. Each actual successful direct or indirect Vulkan compute dispatch records at most eligible single-page copies **after** recording the dispatch. Limits are 32 outstanding private 4 KiB staging loans and 1 MiB issued per frame. No new submission or Vulkan wait is inserted. The host visibility barrier and timeline tick belong to the submission that contains the copy. Ready checks refresh the timeline without waiting.
- A canceled loan continues to occupy a slot until the GPU completes its issuing tick. A completed valid loan remains unavailable for reuse until consumed, invalidated or disabled. At cache teardown, remaining loans go back to the pool tagged with their last actual GPU-use tick. Optional allocation/OOM and host mapping invalidation failures fall back to the original read. Noncoherent candidate buffers require successful host cache invalidation; device loss follows the original fatal-error path.
- A match requires the full current aligned 4 KiB demand, the exact cache slot and its monotonic buffer registration instance, unchanged page write serial and device map generation, exact GPU-owned bytes, a usable retired copy, and a unique physical mapping. Graphics/compute storage, writable texel/XFB ranges, DMA, inline and CPU uploads, query-result copies, external buffer obtains, invalidation, CPU claims and destruction invalidate overlapping copies. Multirange compute writes invalidate but do not promote training. Unknown/untracked or multipage requests use the full baseline path.
- Only the original queued GPU callback may consume a candidate, after collected CPU writes have been applied. Texture flushes still run before buffer work, and query flushes run after. Held query reports disallow use. Monotonic physical report-page tags conservatively exclude semaphore/query pointers, crossing tails and syncpoint-shim backing, including prior aliases; tag collisions only add exclusions. Both unique reverse mapping and registration with report pointers synchronize on the device mapping lock at landing.
- A ready hit copies only intersections of current tracker ownership and the exact GPU-dirty interval set, excluding newly pending guest CPU bytes. The existing per-device landing gate protects concurrent CPU stores. The physical mapping is pinned while copying and clearing those dirty bits. There are no mapping/cache locks held across a GPU wait on this path. Private prefetch never clears guest read traps or changes guest RAM. A miss, an assertion of uncertain identity, or a noneligible area leaves the required original demand and its historical co-downloads available. A real hit may omit the optional historical sweep for that demand only.

## Artifacts

`early-buffer.patch` is the frozen review diff. `linux.log`, `final-linux.log` and `reviewed-linux.log` are distinct Linux build/test snapshots; the third covers the final production source. It passed 4,853 focused assertions but intermittently failed an unchanged async shader ownership test. release-proof-linux.log covers that same production source with a separate test-only lifetime fix. The tests run against the actual BufferCache, physical mapper, memory tracker and a deterministic host-runtime substitute. They exercise ready/late/disabled, observed read training, non-submission, allocation failures, growth cap, cancel/teardown, instance reuse, aliases/reports/remap, CPU overlap including two guarded writer tests inherited from Stitch, partial ownership and a deliberately unreported GPU write to force a VERIFY mismatch. The substitute is not a RADV/Vulkan gameplay result.

Reference comparison uses a temporary page and byte mask only in VERIFY mode. Even when the original flush observes bytes overwritten by the CPU or a mapping changes while it waits, those bytes are not certified. Current command queue order is unchanged, so this experiment primarily targets the host-download part of each queued demand. It does not implement upstream's independent back-thread tick scheduling or change the original GPU::WaitForSyncOperation teardown policy. On a miss or during shutdown there is no new wait on a speculative tick. Repeated semaphore tagging and marker-aware counters are active in a process configured for the experiment, including the marker-present control arm.

## Independent review and integration

The final static pass independently confirmed the allocation-coherence rule, checked VMA invalidation return, pending/ready loan ownership, physical report rejection and late CPU-write masking. Production patch SHA-256 is 0a8f22dabbab09660ef759b9702b5f5af0a8492471648d6e77079b6a2a904535. Optional `pread-after-early.patch` adapts only the context of the independent #836 memory_manager.h declaration hunk, preserving every underlying PREAD edit. It applies after this production patch (the original PREAD patch remains unchanged).

Two initial full-suite runs on the final production freeze reported `async_shader_emission.cpp:198 lifetime.expired()` despite the same-seed case passing in isolation. The pre-existing ThreadWorker increments work_done before the local queued callable is destroyed. A caller can see WaitForRequests return while the wrapper still owns its shader capture. The test-only fix scopes and joins the worker before asserting destruction; no changes to production work scheduling. This patch is separate from the early readback behavior, SHA-256 894afee70c689584d0db54ea182c6fd79bfe6dc9bd4b747f30874b3b48d05c19.
